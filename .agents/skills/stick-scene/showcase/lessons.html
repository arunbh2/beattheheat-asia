Lesson 3

Binary search

If a list is sorted, you never need to check every item. Look in the middle, throw away the half that can't have your answer, and repeat.

  1. Step 1Look in the middle

    The middle card is 31. 42 is bigger, so it can't be on the left.

  2. Step 2Drop half

    Look in the middle of what's left: 61. Too big, so drop the right side.

  3. Step 3Found it

    One card left to check, and it's 42. Three looks instead of ten.

Why it's fast

Every look halves what's left, so the number of looks grows very slowly as the list grows.

Lesson 4

Caching

Fetching from far away is slow. Keep a copy close by the first time, and every later request is almost free.

  1. Step 1Miss

    The shelf is empty, so it's the long walk to the database. Slow.

  2. Step 2Keep a copy

    Put a copy on the shelf next to the desk on the way back.

  3. Step 3Hit

    The same request again is answered from the shelf, with no walk at all.

Words you'll hear

cache hitThe copy was there, so the answer is fast.
cache missNo copy yet, so you take the slow trip.
staleThe original changed but the copy didn't.
evictionThe shelf is full, so an old copy goes.
Check yourself

User #7 changes their name in the database. What does the shelf still hold?
